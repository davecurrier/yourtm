Commands Reference

Complete reference for all YourTM CLI commands, options, and usage examples.

Global Options

These options are available for all commands:

Option Description
--version Display CLI version
--help Display help for command

Project Commands

ytm init

Core

Initialize a new YourTM project in the current directory.

ytm init [options]
Option Description Default
-f, --force Overwrite existing configuration false

Examples

# Interactive initialization
ytm init

# Force overwrite existing config
ytm init --force

ytm create

Core

Create tags, triggers, zones, or variables from templates using an interactive wizard.

ytm create [type] [options]
Option Description Default
[type] Type to create: tag, trigger, zone, variable interactive
-p, --platform <platform> Pre-select platform (skip selection) -
-n, --name <name> Set the name -
-o, --output <path> Custom output path -
-y, --yes Skip confirmation prompts false

Examples

# Interactive wizard
ytm create

# Create a tag
ytm create tag

# Create a trigger
ytm create trigger

# Create a zone
ytm create zone

# Create Google tag with preset name
ytm create tag -p google -n "GA4 Pageview"

Available Platforms

  • Google - GA4, Google Ads, GTM
  • Meta - Pixel, Conversions API
  • TikTok - Pixel, Events API
  • Social - LinkedIn, Twitter, Pinterest, Snapchat
  • E-commerce - Multi-platform tracking
  • Utilities - Custom HTML, cookie consent, data layer

ytm check

Core

Validate configuration and check for issues in your project.

ytm check [options]
Option Description Default
--fix Automatically fix issues where possible false

Examples

# Check for issues
ytm check

# Check and auto-fix
ytm check --fix

Build Commands

ytm build

Core

Compile TypeScript tags into optimized JavaScript bundles for production.

ytm build [options]
Option Description Default
-c, --clean Clean output directory before building false
--sourcemap Generate source maps false
--no-minify Disable minification false
-w, --watch Watch for changes and rebuild false

Examples

# Production build
ytm build

# Build with source maps (for debugging)
ytm build --sourcemap

# Clean build
ytm build --clean

# Watch mode
ytm build --watch

ytm dev

Core

Start development server with hot reload for local testing.

ytm dev [options]
Option Description Default
-p, --port <port> Port to listen on 3456
-h, --host <host> Host to bind to localhost
-o, --open Open browser automatically false

Examples

# Start dev server
ytm dev

# Custom port
ytm dev --port 8080

# Open browser
ytm dev --open

Deploy Commands

ytm deploy

Deploy

Deploy compiled bundles to Cloudflare KV for global edge delivery.

ytm deploy [options]
Option Description Default
-e, --env <environment> Target environment (staging, production) staging
-d, --dry-run Simulate deployment without making changes false
-f, --force Force deployment without approval false
-m, --message <message> Deployment message -

Examples

# Deploy to staging
ytm deploy

# Deploy to production
ytm deploy -e production

# Deploy with message
ytm deploy -e production -m "Added TikTok pixel"

# Dry run
ytm deploy --dry-run

ytm deploy init

Deploy

Set up Cloudflare infrastructure (KV namespace, Worker). Run once per project.

ytm deploy init [options]
Option Description Default
--account-id <id> Cloudflare Account ID interactive
--api-token <token> Cloudflare API Token interactive
--worker-name <name> Custom worker name yourtm-cdn
--env <environment> Environment to set up (staging, production, both) production
--skip-worker Skip deploying the Cloudflare Worker false
--save-credentials Save credentials to ~/.yourtm/credentials.json false
-y, --yes Skip confirmation prompts false

Examples

# Interactive setup
ytm deploy init

# CI/CD setup with env vars
ytm deploy init \
  --account-id $CLOUDFLARE_ACCOUNT_ID \
  --api-token $CLOUDFLARE_API_TOKEN \
  --yes

# Setup both environments
ytm deploy init --env both

ytm deploy versions

Deploy

List deployed versions for an environment.

ytm deploy versions [options]
Option Description Default
-e, --env <environment> Environment (staging, production) staging
-l, --limit <count> Number of versions to show 10

Examples

# List staging versions
ytm deploy versions

# List production versions
ytm deploy versions -e production

# Show last 20 versions
ytm deploy versions --limit 20

ytm rollback

Deploy

Rollback to a specific previous version.

ytm rollback [version] [options]
Option Description Default
[version] Version to rollback to (e.g., v1.2.3) interactive
-e, --env <environment> Target environment staging
-f, --force Force rollback without confirmation false

Examples

# Interactive rollback (shows version list)
ytm rollback

# Rollback to specific version
ytm rollback v1.2.3 -e production

# Force rollback
ytm rollback v1.2.3 -e production --force

ytm rollback quick

Deploy

Quickly rollback to the previous version (one version back).

ytm rollback quick [options]
Option Description Default
-e, --env <environment> Target environment staging
-f, --force Force rollback without confirmation false

Examples

# Quick rollback production
ytm rollback quick -e production

# Force quick rollback
ytm rollback quick -e production --force

ytm rollback history

Deploy

Show rollback history for an environment.

ytm rollback history [options]
Option Description Default
-e, --env <environment> Target environment staging
-l, --limit <count> Number of entries to show 10

Testing Commands

ytm test

Test

Test tag firing on a URL using headless browser automation.

ytm test [url] [options]
Option Description Default
[url] URL to test -
-u, --url <url> URL to test (alternative) -
--urls <file> File containing URLs for bulk testing -
-c, --container <id> Container ID to test from config
-o, --output <file> Output report file (xlsx, json, html) -
--no-headless Run browser in headed mode false
-t, --timeout <ms> Timeout in milliseconds 30000

Examples

# Test single URL
ytm test https://example.com

# Bulk test from file
ytm test --urls urls.txt --output report.xlsx

# Test with visible browser
ytm test https://example.com --no-headless

ytm watch

Test

Watch a URL for tag firing in real-time (continuous testing).

ytm watch [url] [options]
Option Description Default
[url] URL to watch -
-c, --container <id> Container ID from config

ytm diff

Test

Compare tag behavior between two test results or versions.

ytm diff [options]
Option Description Default
-b, --baseline <file> Baseline results file -
--current <file> Current results file -

Examples

# Compare two test results
ytm diff --baseline before.json --current after.json

ytm monitor

Test

Real-time tag performance monitoring in your terminal.

ytm monitor [options]
Option Description Default
-c, --container <id> Container ID from config
-m, --mode <mode> Monitor mode: preview or live preview
-f, --filter <tag> Filter by tag name -

Examples

# Monitor in preview mode
ytm monitor

# Monitor production traffic
ytm monitor --mode live

# Filter by tag name
ytm monitor --filter "GA4"
